# RCA — POST /api/admin/ai/one-click-product returns Cloudflare "invalid/incomplete response" in production

**Deployment:** celesta-staging  |  **Run:** f90ec7c5-dc64-4e27-b8b5-1b02295d4eec (active, success)
**Live URL:** https://celesta-staging.emergent.host — **UP, serving 200.** Template: farm (fastapi_react_mongo_shadcn), Cloudflare frontend, tier_0.

## TL;DR
This is **NOT a timeout**. The one-click endpoint fails **fast (~12s)** because its LLM call is rejected with **HTTP 403 `FREE_USER_EXTERNAL_ACCESS_DENIED`** from the Emergent LLM gateway. The app catches that and returns **502**, which Cloudflare renders as "the origin web server returned an invalid or incomplete response." The timeout hypothesis is disproven.

## Answers to the four questions asked
1. **Is the deployed backend healthy/up?** YES. Live URL returns 200; both replicas (`...-7thsv`, `...-xbvvl`) are `Running`, `ready: true`, `restart_count: 0`; no OOMKilled, no container restarts. Hundreds of other `/api/*` routes return 200 in the same window.
2. **Does this endpoint time out / get killed?** NO. Request flow timing: one-click started `00:57:43`, failed `00:57:55` — ~12 seconds, nowhere near Cloudflare's ~100s or any read timeout. It is not OOM-killed (0 restarts). The app returns a real 502 status in the **uvicorn access log** (`"POST /api/admin/ai/one-click-product HTTP/1.1" 502 Bad Gateway`), i.e. the application emitted the 502 itself — this is an application error path, not a dropped/incomplete connection.
3. **Production logs for the request:**
   ```
   services.ai_categorizer - WARNING - [ai-audit] LLM failed for 'Vitamin C Brightening Serum':
   Failed to generate chat completion: litellm.APIError: OpenAIException - Error code: 403 -
   {'error':'access_denied',
    'message':'Free users can only use Universal Key from within Emergent platform. Please upgrade to paid plan for external access.',
    'code':'FREE_USER_EXTERNAL_ACCESS_DENIED',
    'upgrade_url':'https://app.emergentagent.com/settings/billing'}
   ```
   Preceded by `LiteLLM completion() model= gemini/gemini-2.5-flash; provider = openai` (routed through the Emergent integration proxy using the Universal Key). The 403 occurs during the **AI classification/copywriting** step — before image generation / Pillow composition is ever reached. 3× 502 observed on this endpoint; each has the same 403 immediately before it.
4. **Configured origin/read timeout & CDN timeout:** No `nginx.conf` manifest override exists for this deployment (`get_deployment_manifest` → not_found), so the platform-default farm nginx config is in effect — `/api` uses `proxy_read_timeout 86400` (24h). The origin does not time out this request, and Cloudflare's ~100s window is never approached. **Timeout is not the cause.**

## Root cause
The endpoint's LLM calls use the **Emergent Universal Key** (`EMERGENT_LLM_KEY`, routed via `INTEGRATION_PROXY_URL`). That key is **free-tier and only authorized for use from inside the Emergent platform**. Preview (`celesta-staging.preview.emergentagent.com`) runs inside the platform, so it works and returns 200. Production (`celesta-staging.emergent.host`) is an external origin, so the gateway returns **403 `FREE_USER_EXTERNAL_ACCESS_DENIED`**. The handler maps the failure to a 502, and Cloudflare passes the 502 through with its branded "invalid or incomplete response" page.

This is a **preview-vs-prod environment/credential difference**, not a resource, timeout, or infra fault.

## Recommended fix (in priority order)
**Primary — code change (E1 applies in source):** Switch the AI categorizer/copywriter (and the Gemini image-generation path) from the Emergent Universal Key proxy to the **direct provider key**. `GEMINI_API_KEY` and `GEMINI_TEXT_MODEL` are **already present and non-empty** in the deployment secrets — the app just isn't using them for these LLM calls. Point `services/ai_categorizer` (and the one-click copywriting/image calls) at the direct Gemini API using `GEMINI_API_KEY` instead of the universal-key proxy, so production no longer depends on in-platform Universal Key access. Then redeploy.

**Alternative — user billing action:** Upgrade the Emergent account to a paid plan (per the error's `upgrade_url`: https://app.emergentagent.com/settings/billing), which enables external use of the Universal Key. No code change needed, but it is a recurring paid dependency.

## Secondary observation (not the cause, worth fixing)
The backend runs `uvicorn --workers 1`. While a long one-click request is in flight the single worker is blocked, so the nginx `/health` probe briefly returns 503 (observed liveness/readiness probe 503 flaps at 00:57 and 01:00). It did not cross the restart threshold this time (restart_count 0), but once the AI calls succeed and the full 30–90s Gemini + CPU-heavy Pillow pipeline actually runs, this WILL risk probe-kill and will tie up the only worker. Recommended regardless of the 403 fix: run the heavy generation as a **background task returning a job id** (poll for result), and/or offload CPU-bound Pillow work to a threadpool. This also removes any future exposure to the Cloudflare ~100s limit. It does **not** fix the current 403 — that still requires the credential change above.

## What was NOT reproduced
This is an external-gateway/credential fault (403 tied to plan + origin location). The eph sandbox has no app secrets and cannot reproduce platform-gated Universal Key access, so this RCA is **diagnosed from production logs/events, not reproduced in-pod** — stated honestly.
